# Proposal 0001: v0.4 signed entity submissions and key identity

- Status: **Accepted** (maintainer, 2026-11-14)
- Date: 2026-11-14
- Covers: D7 (entity write path), section 7 open items (`key_id`, signed bytes), key registration.
- `schema.json` is **not** edited by this proposal; the snippets below are drafts for v0.4.

## 1. Key identity

- `public_key`: base64url, no padding, of the 32 raw Ed25519 public key bytes (43 chars).
- `key_id`: base64url, no padding, of the first 16 bytes of SHA-256 of those 32 raw bytes. Always 22 chars (fits `$defs/ids/key_id`).
- `signature`: base64url, no padding, of the 64-byte Ed25519 signature (86 chars).

## 2. Signed bytes

The UTF-8 bytes of the RFC 8785 (JCS) canonical JSON of the whole JSON object with the top-level `signature` member removed. No prefix, no domain tag. Applies to observation submissions, attestations, entity submissions and key-registration proofs.

## 3. Key registration (`POST /v1/keys`)

```json
{ "type": "key_registration", "algorithm": "ed25519", "public_key": "<43>", "created_at": "<rfc3339>", "signature": "<86>" }
```

- Signed by the key itself (proof of possession).
- Server derives `key_id`; stores `level: unverified`, `status: active`, `depth` NULL (no chain; nothing emitted publicly).
- Idempotent on `key_id`. Rate-limited (D5).
- Root key: server holds only the public key (`EATSIGHTS_ROOT_PUBLIC_KEY`), upserted at startup as `level: root, depth: 0`. `eatsights keygen` prints a keypair to stdout and stores nothing.

## 4. Entity submission (`POST /v1/entities`)

Body: array of up to 100 items. Per-item results, not all-or-nothing:
`{ "results": [ { "index": 0, "id": "es_…", "status": "accepted" | "duplicate" | "rejected", "problem": { … } } ] }`.

```json
{
  "id": "es_<26 crockford>",
  "schema_version": "0.4",
  "op": "create",
  "entity_type": "place",
  "entity": { "id": "pl_…", "...": "client fields per schema.json $defs/place" },
  "submitted_at": "2026-11-14T10:00:00Z",
  "contributor": { "key_id": "<22>" },
  "license": "CC0-1.0",
  "signature": "<86>"
}
```

### Server-controlled fields

Rejected if the client sends them:

- place: `osm` (create forces `{ "state": "unchecked" }`; edit keeps current), `record_state`, `merged_into`, `created_at` (set by server on create).
- menu_item: `record_state`, `merged_into`, `created_at`, same rules.

After the server fills these, the stored entity must validate against `schema.json#/$defs/<entity_type>`.

### Permissions

- `create`: any `active` key.
- `edit`: full replacement of client fields. Allowed for level `member` or above, or a key holding a current `vendor_of` for the entity's place. `place_id` of sections and menu items is immutable.

### Idempotency

- Idempotent on the `es_` id: resubmitting returns the original result (`duplicate`).
- `create` with an entity id that already exists with different content → rejected, 409 problem.

### Storage and history

One transaction per accepted item: insert the full signed original into `private.entity_submissions` (the edit history; private because it holds raw `key_id` and signatures), upsert the public entity row, append to `public.changes`.

## 5. Draft JSON Schema (for v0.4 `schema.json`)

```json
{
  "$defs": {
    "ids": {
      "entity_submission_id": { "type": "string", "pattern": "^es_[0-9A-HJKMNP-TV-Z]{26}$" }
    },
    "entity_submission": {
      "type": "object",
      "additionalProperties": false,
      "required": ["id", "schema_version", "op", "entity_type", "entity", "submitted_at", "contributor", "license", "signature"],
      "properties": {
        "id": { "$ref": "#/$defs/ids/entity_submission_id" },
        "schema_version": { "const": "0.4" },
        "op": { "enum": ["create", "edit"] },
        "entity_type": { "enum": ["place", "section", "menu_item", "dish"] },
        "entity": { "type": "object" },
        "submitted_at": { "type": "string", "format": "date-time" },
        "contributor": {
          "type": "object",
          "additionalProperties": false,
          "required": ["key_id"],
          "properties": { "key_id": { "$ref": "#/$defs/ids/key_id" } }
        },
        "license": { "const": "CC0-1.0" },
        "signature": { "type": "string", "pattern": "^[A-Za-z0-9_-]{86}$" }
      },
      "allOf": [
        { "if": { "properties": { "entity_type": { "const": "place" } } },
          "then": { "properties": { "entity": { "not": { "anyOf": [
            { "required": ["osm"] }, { "required": ["record_state"] },
            { "required": ["merged_into"] }, { "required": ["created_at"] } ] } } } } },
        { "if": { "properties": { "entity_type": { "const": "menu_item" } } },
          "then": { "properties": { "entity": { "not": { "anyOf": [
            { "required": ["record_state"] }, { "required": ["merged_into"] },
            { "required": ["created_at"] } ] } } } } }
      ]
    },
    "key_registration": {
      "type": "object",
      "additionalProperties": false,
      "required": ["type", "algorithm", "public_key", "created_at", "signature"],
      "properties": {
        "type": { "const": "key_registration" },
        "algorithm": { "const": "ed25519" },
        "public_key": { "type": "string", "pattern": "^[A-Za-z0-9_-]{43}$" },
        "created_at": { "type": "string", "format": "date-time" },
        "signature": { "type": "string", "pattern": "^[A-Za-z0-9_-]{86}$" }
      }
    }
  }
}
```

Full entity validation (against `$defs/<entity_type>`) happens after server fields are filled, so `entity` is only `object` here.

## 6. Maintainer decisions (2026-11-14)

1. `key_id` and signed-bytes definitions: **accepted as final**. Changing them would break installed clients.
2. `edit` stays **full replacement** for now. Partial patches, if ever needed, come as a new `op`.
3. Entity edit history stays **private** for now.
